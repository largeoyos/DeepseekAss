## 本轮修复的软件问题

1. 带点的领域工具名被严格兼容接口拒绝：发送前转为合法名称，响应和历史映射回领域名称。
2. 无参数工具被模型填入额外设置参数：提供显式传输说明字段，校验后移除；保留领域工具空参数约束。
3. 工具调用 Schema 错误被当成能力缺失：错误分类并最多一次带 Schema 反馈的纠正。
4. 第三章初始/工具上下文超过模型输入预算：按实际配置和工具 Schema 预留预算，仅裁剪可重读资料，保留作者指令及调用配对。
5. 新章提案省略父节点，延迟到批准时才推导：创建提案时绑定当前上游；第三章旧提案已通过 CLI 拒绝，并用原正文重建。
6. 提取重试的输出上限等于上下文窗口，输入预算只剩 1 token：预留真实输入及安全余量；同时保留每次提取失败的原始诊断。
7. 第五章规划输入超预算，但大量窗口被输出上限占用：保留关键输入，按剩余实际窗口降低输出上限，并保证最小可用输出预算。
8. 网络请求失败后被当作 JSON 格式错误再次重试：仅对已收到的无效正文重试 JSON 生成，网络重试交给网关，避免重复等待。
9. 世界书审计遗漏活跃章节缺失快照：审计返回 missing_snapshot_node_ids，并对未同步章节明确告警；切换分支后重新计算。

**最终回归：107 项通过，耗时 28.978 秒；`git diff --check` 无空白错误。** 覆盖 CLI 权限、管理命令、Agent、分支一致性、章节生成、模型网关及世界书。

## 未通过项与后续修订

外部接口的世界书请求最终返回 `Request timed out`，额外的小请求也在 20 秒内未返回。因此没有伪造第五章快照：当前活跃路径共五章，世界书有效快照四个，缺失 `ch0005_v001`。程序的重复网络重试问题已修正，但不能据此宣称外部服务已经恢复。

世界书还存在五条信息级提示，涉及手工初始人物、地点缺少章节来源和细节。人工创建的沈砚与自动提取的沈砚保留为两个 ID，需要后续实体合并；本轮没有自动隐藏或删除。世界书共导出九类数据，内容截至已成功维护的第四章。

全文审读发现以下十处问题，详见 `editorial-notes.json`：

1. 第1章，登船地点不够明确：首章写旧码头售票窗口、看见寄存柜后登船离开，同时又要靠末班船抵达旧码头；主港出发与旧码头目的地应区分。
2. 第2章，复印件承担了原件才可能支持的物证判断：叶青对复印件逆光判断背面透墨和刮改时间，证据力度超过载体能提供的信息。
3. 第3章，部分规划未在正文落实：规划要求处理伤势、核对维护记录，正文改为来不及就医且未打开纸袋；肋伤持续影响行动，但计划执行不完整。
4. 第4章，证据归属交接缺失：第三章末维护记录在沈砚内袋，第四章变成周伯怀里；需要补一次明确交接。
5. 第4章，不同证据被混为一谈：叶青此前持有潮位复印件，维护记录刚得到却未复印；丢失维护记录后不能仅凭潮位复印件声称整条证据链无损。
6. 第4章，控制室锁闭方式矛盾：门起初从内部插死，值班员随后说被从外面锁上；目前缺少对两处锁闭装置的解释。
7. 第5章，无目的的重复航程：邮船已靠旧码头，人物上船绕一圈又回旧码头；重复了首章的空间动机问题。
8. 第5章，物理动作缺乏可信解释：用柔软绳头撬开锈死锁芯缺乏支撑，应换成工具、卸铰链等可信动作。
9. 第5章，证据结论先于取得记录：维护副本尚在陆岑包里，沈砚却已宣布维护记录与其他证据对得上；应在取回核对后得出结论。
10. 第5章，承诺的结局只部分落实：救援结束、陆岑移交调查、周伯认责、信交到周伯手上均完成；父亲正式平反尚未呈现，信未打开使关键情感信息仍然悬空。
